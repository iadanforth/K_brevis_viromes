# Step 11 tree files, for iTOL

## Read this before using the tree

`kbrevis_gvmags.PRELIMINARY_no_support.treefile` is **not the final tree.** It was copied
out of a still-running IQ-TREE job (job 111564) on 2026-11-17 at 09:45, 20 h into a search
that had not finished.

* It has all **1,564 tips** and a real maximum-likelihood topology.
* It has **no branch support values at all** — zero UFBoot numbers. Every branch looks
  equally trustworthy in iTOL, and they are not.
* IQ-TREE was still finding better trees when it was copied (`BETTER TREE FOUND at
  iteration 308: -9852403.676`), so the topology will still change.

Use it to get the layout working in iTOL and to check the annotation files render. **Do not
draw conclusions from it,** and do not put it in a figure. The final
`kbrevis_gvmags.treefile`, with 1,000-replicate UFBoot support, will be added here when job
111564 finishes, alongside `.contree`, `.iqtree` and the RAxML IC/TC scores.

Model selected by ModelFinder (already decided, will not change): **WAG+F+I+R4**.

## How to use these in iTOL

1. Go to https://itol.embl.de/upload.cgi and upload the `.treefile`.
2. Drag each annotation file below onto the rendered tree (or use "Datasets" → upload).

| file | what it does |
|---|---|
| `itol_labels.txt` | renames our 17 tips to `vOTU01 \| SRR28004148`, with `[N genomes]` where a vOTU has several members. Reference tips keep their accessions |
| `itol_tree_colors.txt` | draws our 17 vOTUs' branches and labels in red and bold, so they are findable in a 1,564-tip tree |
| `itol_order_colorstrip.txt` | colour strip for viral order (Imitervirales, Pimascovirales, Pandoravirales, …), colour-blind-safe palette, with a legend |
| `itol_family_colorstrip.txt` | the same for family, for the 10 commonest families (1,361 of 1,564 tips) |
| `itol_popup.txt` | hover text. Ours show completeness, length, nearest GVMAGs V2 relative with ANI/AF, and that reference's family and ecosystem; references show order, family, genus, length and ecosystem |

Suggested first view: **unrooted / circular**, labels off, with the order colour strip and
`itol_tree_colors.txt` on. That shows at a glance which order each of our vOTUs falls in.

## Rooting

The tree is **unrooted**. Booker et al. midpoint-rooted theirs. In iTOL use
"Advanced" → "Midpoint root" before reading anything into the branching order.

## Caveats carried over from earlier steps

* Average pairwise identity in the alignment is **14.5%**, so deep branches will be weakly
  supported however good the tree is. Read support, not just topology.
* **vOTU13** (`SRR28004137_bin_11`) is 74.8% missing data (~1,022 real amino acids). Its
  position is unreliable; treat it as unplaced.
* **vOTU05 and vOTU19 are absent from this tree entirely.** They carried none of the seven
  marker genes, so `ncldv_markersearch` dropped them. vOTU05 is the odd one: CheckV called
  it 100% complete at 203 kb with no GVMAGs V2 relative, yet it has none of the core
  *Nucleocytoviricota* markers and no resolved order. It should not be reported as a giant
  virus genome without further evidence.
